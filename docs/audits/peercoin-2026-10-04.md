# Peercoin support evidence — 2026-10-04

Spectra now catalogs native Peercoin mainnet and testnet. PPC precision is six decimal places, and testnet tPPC has no market identity. Ordinary receive, balance/history, account-address discovery and native transfer flows use the same core ownership as the other UTXO networks. The existing `peercoin` source icon and generated iOS asset are reused.

## Protocol sources

The current [minimum-fee calculation](https://github.com/peercoin/peercoin/blob/master/src/consensus/tx_verify.cpp) is `max(1,000, 10 × complete serialized transaction bytes)`, including witness bytes. Spectra conservatively estimates final signature sizes before signing.

[Reward consensus validation](https://github.com/peercoin/peercoin/blob/master/src/consensus/tx_verify.cpp) measures maturity as the spending height minus the creating height. Spectra conservatively selects coinbase/coinstake outputs only after their verified source transaction reports at least 500 confirmations on mainnet or 60 on testnet; it does not project a future spending height from an immature output. Ordinary outputs are not subject to this reward-maturity policy.

The 0.01 PPC recipient/change floor follows [Peercoin Core's wallet policy](https://github.com/peercoin/peercoin/blob/master/src/wallet/spend.cpp). [Version 3 consensus validation](https://github.com/peercoin/peercoin/blob/master/src/consensus/tx_check.cpp) relaxes the older minimum-output rule; Spectra deliberately follows the reference wallet's ordinary-output policy rather than advertising tiny transfers.

The 21,000,000 PPC `MAX_MONEY` constant constrains individual amounts and transaction sums; the reference source explicitly distinguishes it from a lifetime supply cap. The wiki describes ongoing issuance and fee destruction, without treating that sanity bound as supply.

[SLIP-0044](https://github.com/satoshilabs/slips/blob/master/slip-0044.md) assigns coin type 6 to Peercoin. The catalog defaults to `m/44'/6'/{account}'/0/0` and additionally offers BIP49/BIP84/BIP86 paths; testnet uses coin type 1. Keys may own legacy P2PKH, nested P2SH-P2WPKH, native P2WPKH or Taproot P2TR outputs. [Deployed script validation](https://github.com/peercoin/peercoin/blob/master/src/validation.cpp) enables Taproot under the [protocol V12 fork rules](https://github.com/peercoin/peercoin/blob/master/src/kernel.cpp); the absence of Bitcoin-style BIP9 activation entries in chainparams is not evidence of non-support.

[transaction.h](https://github.com/peercoin/peercoin/blob/master/src/primitives/transaction.h) serializes a timestamp only for versions below 3. Version 3 uses Bitcoin's transaction layout. Input verification decodes old version 1/2 transaction timestamps and verifies the non-witness transaction ID; signing creates version 3 transactions. Hash-verified output scripts are retained rather than replaced with address-derived P2PKH scripts: real minting rewards commonly pay P2PK.

Private-key derivation fixtures come from the official [Cointoolkit address tests](https://github.com/peercoin/cointoolkit/blob/gh-pages/test.html). Their compressed WIF payloads are decoded to raw key hex for Spectra's existing private-key input interface. This does not add a separate WIF importer.

The malformed POST proves the broadcast route is connected to a backend parser. **No funded live transaction was signed or broadcast.** Signing and successful/rejected response handling are covered by local signing vectors and mocked transport tests. Live transaction acceptance remains unverified.

Mainnet block 894599 supplied transaction `6ee6e0213f4cd70e020e208d62fe9c6aeeca6db182516175bf4cef16535b8c8d`, a version 3 coinstake with an empty zero-valued first output and an 8,017.363982 PPC P2PK reward output. Its raw bytes are retained as a hash-verified API fixture. Testnet block 702804 supplied transaction `0171521554435315d7c3a3c52ce25ba6b2ef4e53c11a2f58d741d21aa79d62e2`. The UTXO list omits reward classification, so Spectra must fetch and hash-verify each source transaction before deciding whether its outputs have matured.

A second read of both reward transactions confirmed `fees: "0"` and integer `value`/`valueIn` fields. Their output-minus-input rewards are 25.237911 PPC and 25.933664 tPPC respectively, consistent with six-decimal history amounts.

The backend reports mainnet as `livenet` and testnet as `testnet`. Every Peercoin request verifies coin identity, decimal precision and that network field before reading or broadcasting. A wrong-network endpoint fails before the requested operation.

One mainnet `/block/894600` request returned HTTP 400 during the probe; `/block/894599` and all configured wallet methods succeeded. These spot checks establish present method availability, not an uptime guarantee. Each network currently has one verified public Blockbook endpoint.

The [Coinpaprika PPC record](https://api.coinpaprika.com/v1/coins/ppc-peercoin) confirms the market identifier `ppc-peercoin`; native PPC uses CoinGecko `peercoin`. No wrapped-PPC deployment is added from market-provider contract metadata.

## Deliberate limits and verification

Minting is not enabled by Spectra. It requires participating in proof-of-stake with a compatible wallet and its own lifetime/security model; adding a staking catalog row would incorrectly advertise an absent adapter. The chain and coin wiki communicate this limit. Caller-supplied network/amount assumptions are refused. Transfer fees always come from the complete prepared input/output layout, without a fixed native-fee fallback.

Input selection uses deterministic largest-first ordering. Ordinary amounts consume only the inputs they need; the MAX quote retains a subset within the transaction money bound and a conservative 100 kB serialized-size bound. Near those bounds this greedy subset can miss another valid combination, and a retained change output may make a partial send exceed the size bound. MAX therefore describes the selected subset's capacity rather than an exhaustive search across every combination. Aggregate wallet balances remain complete.

Targeted checks implemented with this addition cover both catalog identities and precision, official raw-key addresses, all four registered address formats, wrong-network/checksum rejection, Taproot account discovery, Funds Finder accounts 0–2, coinbase/coinstake maturity boundaries, ordinary unconfirmed outputs, verified zero-valued outputs, source-transaction identity/value/index checks, duplicate outpoints, old timestamps, witness transaction IDs, requested transaction-status identity and fee precision. Full verification and its final result are recorded in the Peercoin entry of [BEHAVIOUR-CHANGES.md](../BEHAVIOUR-CHANGES.md).

Independent catalog checks already passed: all TOML parses, enum and network order agree, 90 concrete networks have one presentation row each, 50 mainnet ranks are contiguous, and both Peercoin native deployments have six-decimal precision. Owned Rust files pass `rustfmt --check`.
